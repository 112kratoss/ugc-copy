## Product decision

Build one backend-owned search capability and expose it through two platform-specific entry points:

- **Web:** add a search action to the global navigation and a shareable `/search?q=...` page.
- **Mobile:** evolve the existing Showcase tab into **Explore**. The route stays `/(tabs)/showcase` for compatibility; only its visible label and content shell change.
- **Empty Explore:** preserve the current personalized Showcase masonry.
- **Active search:** show `Top`, `Creators`, `Posts`, and `Recipes` tabs.

This is an extension of the current Showcase, creator-profile, and marketplace systems. It is not a separate content store and it does not replace feed ranking.

## V1 scope

### Searchable

| Entity | Indexed fields | Destination |
|---|---|---|
| Creators | username, display name, bio | Existing creator profile |
| Posts | title, body, prompt, source tool | Existing post detail/viewer |
| Recipes | Existing marketplace search document | Existing marketplace detail |

Creator eligibility is deliberately bounded: a profile appears when it has a claimed username or at least one visible public post. Empty accounts with only an autogenerated `creator-xxxxxxxx` handle must not fill results.

### Not in V1

- Comment search
- Search over private/unlisted posts, private generations, draft recipes, emails, or internal workflow names
- Dedicated hashtag pages or hashtag following
- Search suggestions from other users' query history
- Semantic/vector reranking
- External search infrastructure such as Algolia or Elasticsearch
- Inline Follow buttons in result rows
- Trending-query analytics that store raw user queries

## Search contract

Add one optional-auth endpoint:

```text
GET /api/search?q=<query>&type=top|creators|posts|recipes&cursor=<opaque>&limit=<n>
```

Rules:

- Normalize Unicode, trim/collapse whitespace, lowercase for matching, and remove leading `@` for creator matching.
- Reject queries over 100 characters.
- Two-character queries may return creators only.
- Posts and recipes require at least three characters so their trigram indexes stay selective.
- `limit` defaults to 20 and is capped at 24.
- `type=top` returns bounded previews: up to 5 creators, 12 posts, and 6 recipes. It does not paginate.
- Entity-specific tabs return one paginated result page.
- Cursors are versioned, opaque base64url values. They contain only the entity type, stable score/sort tuple, and final ID; clients must not construct them.
- Arbitrary query responses use `private, no-store`. Do not create unbounded CDN cache keys from query text.

Response shape:

```ts
type SearchResponse = {
  query: string;
  normalizedQuery: string;
  type: 'top' | 'creators' | 'posts' | 'recipes';
  creators: SearchPage<CreatorSearchResult>;
  posts: SearchPage<ShowcaseFeedItem>;
  recipes: SearchPage<MarketplaceResource>;
};

type SearchPage<T> = {
  items: T[];
  nextCursor: string | null;
};
```

The response always includes all three sections. Unrequested sections are empty pages. This keeps web/mobile parsing simple while the server avoids querying unrequested sections.

## Non-negotiable safety boundaries

Every post result must satisfy:

```text
visibility = public
archived_at IS NULL
review_status = visible
```

Every recipe must remain listable under the current marketplace policy. Signed-in results must exclude both directions of a block relationship. If block-state lookup fails, signed-in search must fail closed rather than expose results from an unverified relationship.

The browser and mobile clients must not query `profiles` or search-document tables directly. The optional-auth API owns service-role reads, filtering, result hydration, throttling, and response shaping.

## Ranking policy

### Creators

Rank in this order:

1. Exact normalized username
2. Username prefix
3. Exact/prefix display name
4. Full-text relevance
5. Trigram similarity for imperfect spelling
6. Small signed-in boost for already-followed creators
7. Public-post count and latest visible-post recency as tie-breakers

Do not add a follower-count trigger in V1. Follow mutations are a hot path and search does not need another synchronous counter write.

### Posts

Use a weighted full-text document:

- A: title
- B: body
- B: prompt
- C: source tool and source-tool slug

Final score combines text rank with bounded boosts for:

- exact/prefix title match
- trigram similarity
- creator-follow relationship
- recency decay
- `ln(1 + save_count + comment_count + remix_count)`

Text relevance must dominate engagement. A popular unrelated post must not outrank an exact title match.

### Recipes

Reuse `list_marketplace_resource_bundles` and its trigger-maintained trigram document. Do not create a second recipe index. V1 may continue the marketplace's existing sort behavior; relevance-specific recipe ranking can be a separate follow-up if observed results need it.

## Definition of done

- Search finds claimed creators, visible public posts, and listable recipes from both web and mobile.
- Exact creator/post matches rank predictably above fuzzy or popular-but-weak matches.
- Hidden, archived, private, unlisted, blocked, and non-listable content never leaks.
- Post results reuse canonical Showcase hydration and existing destinations.
- Empty mobile Explore remains the current personalized Showcase experience.
- Loading, empty, error, retry, pagination, keyboard, focus, screen-reader, safe-area, and reduced-motion states are verified.
- Database and route rate limits are bounded and measured.
- Clean migration replay, pgTAP, web/mobile tests, lint, typechecks, build, build verification, and E2E gates pass.

## Follow-up candidates after V1 data

- Dedicated hashtag documents and `/explore/tags/[tag]`
- Query autocomplete using creators/tools, not other users' raw query history
- Relevance feedback such as result-open rate and reformulation rate with a privacy-reviewed retention policy
- Recipe relevance scoring rather than current marketplace ordering
- Semantic reranking using the existing optional pgvector foundation, only after a durable embedding pipeline and freshness monitor exist
- Search suggestions personalized from follows and explicit feed interests
