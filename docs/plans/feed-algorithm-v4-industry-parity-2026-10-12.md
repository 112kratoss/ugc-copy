# Feed algorithm v4 — closing the gaps to the industry leaders

_Date: 2026-10-12. Design and implementation contract. Follows `feed-algorithm-v3-x-adoption-2026-10-11.md` (v3 is live since 2026-10-12 04:26 UTC). The rating that motivates this: architecture 8/10, fresh-content/fairness 8/10, repeats 7/10, safety 6/10, measurement 5/10, signals 4/10, ranking model 3/10, interests 3/10, content understanding 2/10._

## 1. What changes, by gap

| Gap | Leaders | v4 |
|---|---|---|
| **Content understanding 2→7** | Multimodal embeddings; clusters; near-duplicate suppression; item-to-item retrieval | `gte-small` (384-d) text embeddings of every post's title + description + prompt + tool + category, computed inside a Supabase Edge Function (`Supabase.ai.Session('gte-small')`, no external API, no key); k-means clusters (`feed_semantic_clusters`) refreshed by a job; near-duplicate canonicalisation (cosine ≥ 0.95 → the newer post is a duplicate of the older); a `semantic` candidate pool from the viewer's **taste vector** (mean embedding of what they saved/remixed/meaningfully engaged with, 90 d); a `semantic_similarity` feature; the existing `max_semantic_cluster_per_20` rule finally has clusters to act on. |
| **Interests 3→6** | Behavioural interest graph | `semantic_cluster` becomes a `user_interest_weights` dimension (fed by the same events as the others), so `interest_match` reads fine-grained taste, not just image/video/text. |
| **Signals 4→7** | Watch time, completion, shares, replies, follows, dozens of negatives from every surface | Home (web + mobile) emits `dwell` and `media_progress` for inline autoplay and `save` on mobile Home; `resource_open` finally has emitters; **new `comment` event**; `follow`, `remix_complete` and `purchase` are written **server-side** by their authoritative actions (with the delivery id when the client passes one). Post stats, meaningful engagement, interest weights and the usefulness term all learn the new signals. |
| **Ranking model 3→5** | Deep models predicting per-user action probabilities, trained on logged impressions | A training pipeline, not a neural net: `npm run ops:feed-ranker -- train` fits per-action logistic regressions (meaningful, quick-skip, negative) on the durable delivery facts, with position as a feature and exploration propensity as a weight, scores them on a session-split holdout, replays logged sessions offline against the live weights, and emits a **draft** algorithm version whose `weights` are the fitted value model. The serving path is unchanged — a fitted weight set over the same features is exactly what the versioned `weights` JSON already is. It refuses to emit below a sample floor unless forced. |
| **Measurement 5→7** | Hundreds of experiments, holdouts, viewer-grain metrics | `feed_viewer_daily` (viewer grain) → sessions/viewer, D1 and D7 return, the 7-day meaningful-creation rate (joins `generations`), sample-ratio check per experiment, position-bucket and format breakdowns in `scorecard`. |
| **Safety 6→7** | Account-level labels propagated from content with TTL | `account_labels` (`nsfw_account`, `negative_feedback_account`, `spam_account`, 7-day TTL) written by the maintenance job from `is_nsfw` posts and creator negative rates; recommendation-level (non-follower) exclusion in SQL and in the visibility stage. |

Deliberately not in v4: in-session re-ranking blocks (frozen sessions and cursors stay — it changes pagination semantics), image embeddings (text provenance is rich enough for AI media; CLIP later), learned retrieval.

## 5. Workstream O — Ops: trainer and scorecard v2

- **`scripts/ops/feed-ranker-train.ts`** + `package.json` `"ops:feed-ranker": "tsx --env-file-if-exists=.env.local scripts/ops/feed-ranker-train.ts"`. Pattern: `scripts/ops/feed-algorithm.ts` (injectable client/output, dry run by default). Commands: `dataset [--days 30]` (prints row counts, positives per action, by version), `train [--days 30] [--value-meaningful 1] [--value-skip -0.5] [--value-negative -3] [--min-rendered 500] [--min-positives 50] [--apply] [--force]`, `replay [--days 30] --weights <json>` (offline replay only).
  - Dataset: `feed_delivery_facts` with `rendered_at IS NOT NULL` in the window; features from `score_components` (the 12 feature keys + `semantic_similarity` when present, else 0; `position`; `is_following`, `served_recently`, `is_exploration`), labels: `meaningful` (replicate `is_meaningful_feed_engagement` in TS: video progress ≥ 0.5 by `posts.category`, else dwell ≥ 3 s, or saved/remix/resource/purchase/comment), `quick_skip` (`quick_skipped_at`), `negative` (`not_interested_at`/`hid_creator_at`/`reported_at`). Weight rows by inverse exploration propensity where `exploration_propensity` is in (0,1] (deterministic 1/0 today → weight 1; say so in the output).
  - Model: L2-regularised logistic regression per label by full-batch gradient descent in pure TS (no new dependency), features standardised, position as a feature; evaluation on a holdout split **by session id** (80/20, seeded): log-loss and AUC vs a constant-rate baseline. Serve-time score = `Σ_a value_a · p̂_a(position = 1)`; map to the versioned `weights` by linearising: `w_k = Σ_a value_a · coef_{a,k} · p̂_a(1 − p̂_a)` evaluated at the feature means (first-order), then rescale so the positive weights sum to the live row's positive sum; keep every key the normaliser accepts and clamp to its bounds.
  - Replay: for each logged session in the holdout, re-rank its served items by the live weights and by the fitted weights (both over the stored features), and report the top-12 meaningful rate and quick-skip rate of each, with the number of sessions. Below `--min-rendered`/`--min-positives` the command prints everything but refuses `--apply` unless `--force`.
  - `--apply` → `create_feed_algorithm_version_draft` with description "Fitted <date>: <n> rendered, AUC meaningful/skip/negative …", the fitted `weights`, and the live version's `retrieval_config`/`diversity_config`.
- **`scripts/ops/feed-algorithm.ts` scorecard v2**: `scorecard` adds sections from `feed_scorecard_viewers`, `feed_scorecard_positions`, `feed_scorecard_formats`; `experiment srm --key <k>` prints assignment vs allocation with a chi-square statistic and a plain verdict. `docs/feed-algorithm-operations.md` gains "Training a version from data" and "Reading the viewer-grain scorecard".
- Tests: `src/__tests__/feed-ranker-train.test.ts` (dataset labelling matches the SQL definition on fixtures; logistic regression recovers a planted separable signal; holdout split is by session; the linearised weights pass the normaliser; the sample floor refuses `--apply`; exact RPC payload) and the scorecard additions in `feed-algorithm-ops.test.ts`.
