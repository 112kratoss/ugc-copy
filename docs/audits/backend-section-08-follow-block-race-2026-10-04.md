# Section 8C — concurrent follow and block persistence

October 4, 2026. SOCIAL-02/SOCIAL-03 and DB-03 partial evidence. Candidate follows
8B's save-counter prevention work; these are separate defects.

## Reproduction

The follow guard checks blocks before inserting; the block trigger removes
visible follows after inserting. Neither coordinates with an uncommitted
transaction for the other operation. Holding a follow INSERT open while a block
commits leaves both rows after the follow finally commits. Even the block
service's additional DELETEs can miss that uncommitted follow. The opposite
transaction order reproduces the same database invariant failure.

The permanent actual PostgreSQL baseline fails all four order/direction cases;
sequential blocking and explicit unblock controls pass. No production contention
probe was run. A read-only production inventory found zero follows across blocks,
so there is no identified relationship repair to perform.

A separate real local PostgREST probe commits a block after the service's
precheck but before its follow INSERT. The existing database guard correctly
rejects insertion with 23514, but the service reports 500. This case failed before
the response mapping change, while three earlier follow transport controls passed.

## Change

The existing private follow and block trigger functions acquire the same
transaction advisory lock for the sorted pair of users. A block waits for an
already-admitted follow to commit, then removes it; a follow waits for a preceding
block and then rejects it. The existing trigger bindings and service-only grants
are retained. Blocking in either direction uses the same pair key.

The follow service maps only the guard's specific 23514/message combination to
its existing 404 creator-unavailable response. Other constraint errors remain
500; no successful follow or notification is reported for a rejected insert.
Migration: `20261004121413_serialize_follow_block_relationships.sql`, generated by
the pinned CLI using UTC. No client contract change or mobile runtime change.
