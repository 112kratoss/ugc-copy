# Kling / MiniMax-Hailuo / HappyHorse research (2026-08-24)

## kling-3.0-video (kling-3.0/video)
**Official**: formula **Subject + Subject Movement + Scene + Camera Language + Lighting + Atmosphere**, plain prose scene-direction (kling.ai/blog/kling-ai-prompt-guide). Subject visually concrete; movement = visible, sequential over time. Camera natural language: push-in, pull back, pan, tilt, tracking, orbit slowly, static camera. **One main camera move per shot**; "make it cinematic" = named anti-pattern. Multi-shot: automatic (prose) vs Custom Multi-Shot; inline label syntax `[Shot 1: Wide shot] …` per line + global style tags; setting/characters/style BEFORE shot breakdown; each shot one beat; ≤6 shots, 3–15s. Dialogue (3.0 family, native audio): bracketed speaker tags + tone, action bound before line — `[Character A: Black-suited Agent, controlled serious voice] says: "…"`; "Immediately" for no-pause switches; never pronouns (fal Kling 3.0 guide). Kie's kling-2.6 example: `Scene: … Lines: [African female host, in a cheerful tone] says: "…"`. Text rendering: exact words, placement, surface, camera distance, short.
**Kie** (docs.kie.ai/market/kling/kling-3-0): prompt (no documented max), image_urls (1=first frame, 2=first+last; multi-shot→first only; required if @element referenced), sound (default false; defaults TRUE in multi-shot), duration "3"–"15", aspect_ratio 16:9/9:16/1:1, mode std(720p)/pro(1080p)/4K, multi_shots bool, multi_prompt (**max 5 shots** — app UI allows 6; each ≤500 chars, duration 1–12s), kling_elements (**max 3**; image element = 2–4 imgs ≥300px; video element = 1 clip 3s+, 3–8s effective via start/end ms; optional element_input_audio_urls 5–30s). **Each @element mention costs 37 chars of shot budget. No negative_prompt, no cfg, no camera params.**
**Community**: overpacking = #1 multi-shot failure; keep shot descriptors consistent verbatim; 2–4s per shot sweet spot; 1s shots read as flicker; i2v = prompt the evolution, not the frame.
**Recipe**: (1) flowing prose scene-direction, kill tag lists; (2) scene → subject → sequential action → camera → lighting → atmosphere; (3) one camera move/shot with framing + direction + speed; (4) ban bare "cinematic"; (5) chronological actions "then/as/while", no stacked simultaneous verbs; (6) dialogue `[Name/Role, tone] says: "…"`, action bound first, no pronouns, "Immediately" for turn-taking, sound:true when dialogue; (7) multi-shot ≤5 via multi_prompt, ≤500 chars, 2–4s each, durations sum to total; (8) identical subject descriptors every shot; @names match kling_elements exactly (37 chars each); (9) i2v: delta only; (10) avoidances positive (no negative field); (11) sub-1500 chars, front-load; (12) on-screen text: quoted, placed, ≤3 words.
**Gaps**: single-shot prompt cap undocumented; "image_urls required when elements referenced" odd + untested.

## kling-3.0-turbo (kling/v3-turbo-*)
**Official**: same Kling 3.0 language; Turbo (Jun 17 2026) = speed tier 720p/1080p. Kie's spec example is a full dialogue scene (prose register confirmed).
**Kie**: t2v prompt **max 2500 chars**, duration 3–15, AR 16:9/9:16/1:1, resolution 720p/1080p. i2v adds image_urls (single start frame), drops AR. **No sound param, no multi_shots, no elements, no negative.**
**Community**: Subject/Motion/Camera/Setting brief; failure modes = static description, vague camera, many actions. **Audio DISAGREEMENT: evolink says silent; picsart/artlist claim audio. Via Kie no audio switch — treat as silent, don't promise dialogue audio.** Workflow: iterate 720p Turbo → redo hero shots on kling-3.0-video pro/4K.
**Recipe**: (1) ONE scene, one action arc, one camera move — never a shot list; (2) ≤2300 chars; (3) explicit motion over time (static description = top failure); (4) camera = framing + single named move; (5) i2v: delta only; (6) no dialogue-audio promises via Kie — "she mouths…" or route to kling-3.0-video/o3 with sound; (7) one beat ≤6s, two beats ≥8s; (8) tight wardrobe details (Turbo drifts on long prompts); (9) avoidances positive.

## kling-o3 (kling-3.0-omni/*) — Kling VIDEO 3.0 Omni
**Official** (kling.ai/quickstart/klingai-video-3-omni-model-user-guide): "Images, videos, elements, and text you upload are all treated as prompts." Elements = named subjects referenced **@Name in prose**. Verbatim patterns: `Shot 1 (2s): Wide shot, @Boxer A and @Boxer B face off…`; timestamp form `[00:00 - 00:02] Medium shot: @Goro gestures… Audio: The faint crackle…` (per-shot Audio: cues official); `Cut to` transitions; dialogue `@Grace says, "Hey! Watch your dog!"`. Element types: multi-image subject (2–4 multi-angle imgs; +optional 5–30s voice binding) or video-character subject (3–8s single-person clip; extracts appearance AND voice; voice "does not need to be specified again"). App-side: ≤7 images/elements without video input, ≤4 with. Anti-drift: multi-angle references stop morphing ("102%" subject-stability claim).
**Kie** (v3-omni-*): prompt **1–3072 chars**. customize_multi_shots (default TRUE) vs prefer_multi_shots (model-planned) — mutually exclusive. multi_prompt ≤6 shots {≤512 chars, 1–15s}; required when customize=true. elements[]: {name (@name), description, element_input_urls (2–4 imgs OR exactly 1 video — never mixed), element_input_audio_urls[]}. Caps ≤7 multi-image subjects; ≤3 video subjects; mixed ≤3v+≤4i. i2v: exactly 1 first frame (AR 0.4–2.5), aspect may be auto. r2v: image_urls plain refs, refs+subjects ≤7 (≤4 with video subjects); optional video_urls. audio bool (default false), resolution 720p/1080p/4k, duration 3–15. **No negative/cfg/camera params. App sends flat image_urls; elements unwired pending subject-grouping UI.**
**Community**: prompt = camera/mood/action, NOT re-describing references; one steady text description per subject; ≤2 named subjects + ≤4 shots for reliable 15s pacing; 4K = 67 cr/s — iterate at 720p; assign each reference one job.
**Recipe**: (1) set multi-shot mode explicitly (shots→customize+multi_prompt; single→both false; "model directs"→prefer only); (2) @Name spelled exactly as elements[].name; introduce each in first shot with minimal role phrase, then verbatim; (3) element descriptions pin wardrobe/props — prompt doesn't re-litigate appearance; (4) one camera + one beat per shot; Cut to; ≤6 shots ≤512 chars; durations sum; (5) `Shot N (Xs):` or `[00:00 - 00:02]` prefixes (both official); (6) dialogue `@Name says, "…"` + tone; audio:true when dialogue/SFX; per-shot Audio: lines; (7) r2v: state each ref's job; (8) ≤3072 chars — trim adjectives before structure; (9) never mix imgs+video in one element; (10) avoidances positive; (11) 4K only final renders.
**Gaps**: 37-char @cost documented only for kling-3.0/video; prefer_multi_shots behavior unverified; elements not live-tested.

## hailuo-2.3 (hailuo/2-3-image-to-video-{standard,pro})
**Official**: MiniMax camera syntax works: **15 bracket commands** [Truck left/right] [Pan left/right] [Push in] [Pull out] [Pedestal up/down] [Tilt up/down] [Zoom in/out] [Shake] [Tracking shot] [Static shot]. Inside one bracket = simultaneous (≤3, comma-separated); brackets at different points = sequential. Natural language works but commands more accurate (platform.minimax.io t2v docs). MiniMax API: prompt ≤2000; **prompt_optimizer defaults TRUE** (server rewrites); fast_pretreatment. 2.3 strengths: full-body motion/dance, micro-expressions, anime consistency, e-commerce object stability; i2v single first frame.
**Kie**: **i2v ONLY via Kie**; prompt ≤5000 + image_url both required; duration "6"|"10" (**10s NOT supported at 1080P**), resolution 768P/1080P, nsfw_checker. Pro = identical schema, higher fidelity. No aspect (follows image), no audio, no negative, no optimizer toggle.
**Community**: "storyteller" model — flowing narrative prose beats tags; sequence "then/while/meanwhile"; strong motion adjectives. i2v: prompt the DELTA only; brief subject anchor ("The red-haired woman…") then action prevents subject swap. Don't request framing contradicting the input. No "8k/masterpiece" spam (→ oversaturated deepfry). On-screen text 1–3 words max. Sweet spot 1–2 short paragraphs.
**Recipe**: (1) never describe what the image shows — motion delta only; (2) ≤8-word subject anchor matching image, then action; (3) MiniMax bracket commands, ≤3/bracket, ≤2 camera phases; (4) "then/as/while" present tense; (5) framing consistent with input; (6) one subject-transformation max; (7) strip quality spam; (8) 6s default; 10s only at 768P; (9) 300–1200 chars; (10) prompt_optimizer likely ON upstream — clean prose, no token hacks; (11) no dialogue/speech lines — express emotion visually; (12) anime inputs: name style once.

## minimax-h3 (minimax-h3/*) — Hailuo 3.0/03 (WAIC Jul 17 2026; public Jul 31; base weights open Aug 3)
**Official**: one omni-modal transformer text/image/video/audio; **native stereo audio (dialogue+SFX+room tone) in the same pass**; 2K, 4–15s, 24fps. Instruction-style multimodal referencing in plain language: "Reference the Hitchcock camera movement from Video 1, have the character in Image 2 sing, with vocals matching Audio 3." Audio refs cannot be sent alone. i2v and reference mode mutually exclusive.
**Kie**: prompt **1–7000 chars**. t2v: aspect_ratio REQUIRED (21:9/16:9/4:3/1:1/3:4/9:16 — no adaptive), duration 4–15 (default 6), resolution **768P|2K** (default 2K, exact uppercase). i2v: first_frame_url and/or last_frame_url (one required). r2v: reference_image_urls ≤9 (side 256–5760px, AR 0.4–2.5), reference_video_urls ≤3 (2–15s each, ≤15s total), reference_audio_urls ≤3 (must accompany image/video), aspect incl. adaptive. **No audio toggle (native audio inherent), no negative, no optimizer flag.** First 5 input images free, then 8 cr/img (app caps refs at 5).
**Community** (apidot H3 guide): nine-line formula: subject → scene/time → chronological action → camera framing+movement → lighting/style → **audio/dialogue/timing** → reference assignments → continuity constraints → avoid-list. **Timestamp beats first-class**: `0–5s: … 5–10s: … says, "…" 10–15s: …`. One speaker at a time for lip-sync. **Reference job assignment golden rule**: "Image 1 controls Character A's identity. Image 3 controls environment and lighting only. Video 1 controls body movement and timing only. Audio 1 controls rhythm only. Never transfer facial traits from Image 3." Unassigned refs get blended. ONE dominant camera move; kill drift with "static locked camera, no camera movement, no shot change"; avoid "cinematic/dynamic". Explicit Audio: lines with timing; end product prompts with exclusions ("No extra text, no additional products, no shape changes") — honored despite no negative field.
**Recipe**: (1) timestamped beats matching duration; never more story than seconds; (2) one dominant camera instruction; append static-lock formula for stillness; (3) ALWAYS an Audio: line — H3 renders sound regardless, so direct it; (4) dialogue: speaker + quoted line + timestamp; one speaker at a time; "accurate lip sync for [speaker] only" in 2-person scenes; (5) r2v: one "controls" sentence per ref in array order; forbid cross-transfer; (6) i2v: delta; last_frame only when end-state matters; (7) preserve clause (faces, wardrobe, product geometry, logo) for commercial; (8) close with explicit exclusions; (9) t2v needs explicit aspect_ratio; (10) 8–12 lines complex scenes; 7000 cap not a target; (11) one visual style per generation; (12) change one variable per iteration.
**Gaps**: MiniMax platform docs hadn't listed H3 at fetch; whether Kie disables upstream optimizer unknown.

## happyhorse-1.1 (happyhorse-1-1/*)
**Identity**: **Alibaba/Taotian Group "Future Life Laboratory" (ATH AI unit), led by Zhang Di — ex-Kuaishou VP, technical architect of Kling** (CNBC 2026-04-10). Debuted anonymously ~Apr 7 2026 on Artificial Analysis arena, #1 T2V and I2V before reveal. 1.1 (Jun 23 2026): **single-pass audio+video with lip-synced dialogue in 7 languages** (EN, Mandarin, Cantonese, JA, KO, DE, FR); 1080p/24fps, 3–15s; served via Alibaba Cloud Model Studio (Bailian)/Qwen app. Weights conflict (CNBC: 15B open for 1.0; invideo: closed hosted).
**Kie**: prompt any language, **≤5000 non-Chinese chars / 2500 Chinese; overflow SILENTLY truncated**. t2v: resolution 720p/1080p (default 1080p), aspect 9 options (16:9, 9:16, 1:1, 4:3, 3:4, 4:5, 5:4, 21:9, 9:21), duration 3–15. i2v: image_urls (first frame). r2v: reference_image ≤9 (shortest side ≥400px) with official syntax: **"use [Image 1] and [Image 2] to refer to the corresponding reference image… order must match the array. When using a reference, specify the object, such as 'the woman in a red qipao in [Image 1]'."** No audio toggle (native audio), no negative.
**Community**: quote dialogue + **name the language**; "no dialogue" for silent clips; one shot/action per generation. Example: "Medium close-up, a woman in a rain-soaked Tokyo alley looks into the lens and says in Japanese: 「もう戻れない」— neon reflections, handheld, shallow depth of field, night." Weaknesses: garbled on-screen text; lip-sync drifts on crowded/fast-cut; physics artifacts grow with duration. Strengths vs Seedance: character consistency, reference-driven work, controllable storytelling.
**Recipe**: (1) one shot, one action, one camera move; (2) audio always generated: script it (speaker + quoted line + language named) or "No dialogue, ambient [X] only."; (3) front-facing uncluttered framing for dialogue; (4) r2v: "the [described object] in [Image N]" in array order, one role each; (5) Kling-style prose (shared DNA): setting → subject → action → camera → light; (6) ≤~2000 chars (silent truncation at 5000); (7) Chinese prompts fully supported — don't translate user CN; (8) avoid on-screen text entirely (garbles); (9) ≤10s for physics-heavy scenes; (10) 9 aspect options incl. 4:5/5:4/9:21; (11) no negative field — inline exclusions.
**Gaps**: no official Alibaba prompt handbook in English; upstream prompt-extension unknown.

## kling-2.6 motion control (kling-2.6/motion-control)
**Official** (kling.ai/quickstart/motion-control-user-guide): **video = choreography, image = identity, prompt = context.** FAQ: "Your text prompt should mainly guide scene, lighting, style, and atmosphere… Over-directing movement in text can fight the reference motion and reduce coherence." "You do not need to describe the action… describe the scene. 'A cinematic shot, neon lighting, cyberpunk city, 4K resolution, volumetric fog.'" Official examples: `A girl wearing a white tank top and a denim skirt.` (wardrobe restyle) and `A corgi runs in, circling around a girl's feet.` (**adding secondary element allowed** — as long as main character's motion isn't redirected). Inputs: match half-body↔half-body / full↔full; motion ref = single continuous shot, no cuts/camera moves, moderate speed, minimal displacement, whole body+head visible, 3–30s (model extracts valid continuous segment; short extraction = shorter non-refunded output). character_orientation: video (default; motion+camera+facing follow video, ≤30s) vs image (facing follows image, ≤10s, **camera moves become promptable**: Zoom In/Out, Camera Up/Down, Fixed).
**Kie**: prompt optional ≤2500 (default "The cartoon character is dancing."); input_urls exactly 1 image (AR 2:5–5:2, head+shoulders+torso visible); video_urls exactly 1 (3–30s); character_orientation required; mode 720p|1080p. No negative, no duration field (output = extracted motion length).
**Community**: prompt = "production direction, not choreography"; verify transfer with minimal prompt first, then enrich. Warping causes: framing-scale mismatch (full-body ref on portrait image → warped face), hidden limbs the motion needs (hands in pockets + waving ref → 6-finger glitches), no breathing room, low-contrast/cluttered ref background. **You are not stuck with the reference video's background — prompt the new environment.**
**Recipe**: (1) NEVER describe motion/dance/gesture timing/tempo; (2) DO write: who (wardrobe, age, role), where, lighting, style; (3) identity consistent with image — reinforce, don't contradict; (4) environment swaps in prompt — that's the feature; (5) secondary elements OK, never a second performing character; (6) camera language only when orientation=image; (7) stability clause: "stable background, consistent lighting, no distortion."; (8) 1–3 sentences; (9) never motion negations ("don't move the arms") — fighting/jitter; (10) choreography in user prompt → strip it, keep identity/setting words.

## kling-3.0 motion control (kling-3.0/motion-control)
**Official**: all 2.6 rules + upgraded facial consistency; app adds facial Element Binding (face-only ref; app-only, not on Kie). Multi-person first frames: largest person becomes subject. Cross-species faces degrade. **Kie default prompt = official hint: "No distortion, the character's movements are consistent with the video."**
**Kie**: same shape as 2.6 (prompt 0–2500, input_urls, video_urls, mode std/pro, character_orientation optional default video) **plus background_source: input_video (default) | input_image (use the character image's background)** — API-level environment control 2.6 lacks.
**Community**: same warping playbook; align identity image and motion ref in camera angle/lens/lighting; avoid extreme expression instructions (face-warp trigger). 3.0 preserves micro-expressions, weight shifts, outfit details.
**Recipe**: (1) all ten 2.6 rules; (2) prefer background_source=input_image to keep the character image's setting; prompt only environments in NEITHER input; (3) with input_video, describe intended environment anyway to stabilize; (4) append official stabilizer sentence when user prompt is short; (5) no extreme-expression directives; (6) multi-person image: name which one; (7) route 3.0 for close-up faces/long takes, 2.6 for cost.

## Cross-cutting
1. **No negative prompts anywhere in this scope** (all 8 endpoints verified). Convert avoidances to (a) positive phrasing, or (b) inline exclusion sentences for MiniMax/Alibaba family ("No extra text, no additional products") which H3/HappyHorse honor.
2. **Camera control is prompt-text only via Kie** — no preset params. Kling: natural-language one move/shot; Hailuo 2.3: 15 [Bracket] commands; H3: one named move in prose; HappyHorse: prose. Per-family camera grammars needed.
3. **Three shot-delimiter dialects**: Kling inline `[Shot 1: Wide shot]` / `Shot 1 (3s):` / `[00:00 - 00:02]`; Kling structured multi_prompt[] arrays (5@500 kling-3.0/video, 6@512 o3); H3 `0–5s:` timestamp lines. Prefer array fields when UI collects shots.
4. **Reference-mention syntaxes differ**: Kling `@element_name` (must match elements[].name; 37-char cost); HappyHorse `[Image 1]` positional; H3 "Image 1 controls X" role sentences.
5. **Native audio routing**: always-on minimax-h3 + happyhorse-1.1 (script or silence explicitly); opt-in (sound/audio) kling-3.0-video/o3; absent via Kie on turbo + both motion controls.
6. **Server-side rewriting upstream**: MiniMax prompt_optimizer default true; probably Bailian for Alibaba; no toggles on Kie → assume second rewrite; clean semantic prose. No documented rewriting on Kling.
7. **Universal anti-patterns**: >1 camera move/shot; "cinematic" without instruction; describing the i2v start image; quality-word spam; more story than seconds; multiple variable changes per iteration; inconsistent subject descriptors.
8. **Length ceilings**: turbo & motion-controls 2500; o3 3072 (+512/shot); kling-3.0-video 500/shot multi; hailuo 5000 (aim ≪2000); h3 7000; happyhorse 5000/2500 silent truncation. Sweet spot 60–200 words single-shot.
9. **Motion-control is the inverted case** — the only endpoints where motion words are HARMFUL. Enhancer must branch hard: strip choreography, keep identity/environment/style, leverage background_source (3.0).
10. **App notes**: models.ts routes kling-3.0-turbo AND kling-o3 through enhancerModelId 'kling-3.0-video' — Turbo needs a single-shot/no-audio variant, O3 needs @elements/audio-aware variant; the three should NOT share one profile. Local kling-3.0/video ref predates 4K mode + audio-element fields.
