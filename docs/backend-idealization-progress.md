# Backend Idealization Progress

Last updated: 2026-06-23

## Goal

Make the shared backend for web and mobile production-ready, cost-efficient, performant, and scalable using Vercel Pro plus Supabase Pro.

## Overall Progress

**Total completion: 98.7%**

- Completed milestones: **222**
- Open completion gates: **3**
- Active workstreams: **0**

The percentage is `completed milestones / (completed milestones + open completion gates)`. Active workstreams are status-only and are excluded because they duplicate open completion gates. Update this block whenever a checklist item is added or completed; `src/__tests__/backend-idealization-progress.test.ts` verifies that the displayed counts and percentage match the checklist.

The target architecture is:

- Vercel is the API/business-logic boundary for both web and mobile.
- Supabase is the source of truth for Auth, Postgres, Storage, RLS, atomic RPCs, job locks, and durable state.
- Clients never own pricing, provider routing, credit settlement, payment trust, or generation validation.
- Expensive and failure-prone work is cached, rate-limited, idempotent, observable, and retry-safe.

## Completion Rule

An item is marked complete only when the current repo contains the implementation and there is relevant verification evidence. Production-only items remain open until the deployed environment is checked.

Use this convention:

- `~~completed item~~` means completed in the current local codebase.
- `in progress` means implementation exists but verification or cleanup is still ongoing.
- `open` means the work still needs to be implemented or audited.
