# Mobile releases: store builds and OTAs

Moved unchanged from `AGENTS.md` on 2026-10-18 so it loads only where it applies; the core file keeps a summary and points here.

- **Mobile ships separately** — merging to `main` never reaches phones. Store binaries go out via `mobile-store-release.yml` (manual dispatch + store review); do not push to `main` while a store-release run is in flight — the push cancels it at the submit gate. JS-only fixes can ship OTA via expo-updates, but an `eas update` only reaches binaries whose runtime fingerprint matches **exactly** — publishing at any other value reports success and reaches zero devices. `ugc-mobile/ota-targets.json` records the fingerprints of the binaries actually in users' hands, and `ugc-mobile/scripts/verify-ota-target.mjs` refuses a mismatched publish; update that file in the same commit that ships a new binary, never to silence the preflight (`npm ci` in `ugc-mobile` can change the working-tree fingerprint). **Publish OTAs only with `node ugc-mobile/scripts/publish-ota.mjs --platform <ios|android|all>`** — a dry run until `--publish` (add `--rollout <pct>` to stage). It builds in a throwaway worktree at an origin/main commit (never from a checkout whose `.env.local` has empty RevenueCat keys), sets aside the files a target lists under `setAside` in `ota-targets.json`, refuses a rollback of a newer live update or a republish with no mobile changes, exports with `--source-maps` (without it Hermes embeds ~40% debug info), checks the artifact against production values inside `eas env:exec production`, then uploads those exact bytes. Metro's transform cache (`$TMPDIR/metro-cache`) is shared by every tree on the machine and keyed without `EXPO_PUBLIC` values, so any production export made by hand must get a private `TMPDIR` or `--clear`, or it can inline another tree's placeholders. Android runs R8 in one deliberately pinned shape (enforced by `ugc-mobile/plugins/withAndroidReleaseSafety.js`, widened one switch per device-verified build in #112): minification on, the optimizing `proguard-android-optimize.txt` base, `android.enableR8.fullMode=true`, resource shrinking on R8's optimized pipeline (`android.r8.optimizedResourceShrinking=true`), and the keep rules in `ugc-mobile/plugins/android-release.pro`, which hold expo-modules-core's runtime (`expo.modules.kotlin.**`) and a few named reflecting modules optimizable but never shrinkable — Google Play scores each bundle's obfuscation (0.1.3 measured 1% against a 25% threshold, fix by Feb 2027). Build 62 shipped unusable because its rules let R8 shrink that runtime, which converts module records by reflection; full mode and the optimizer were cleared of blame, and the R8 inspector reported build 62's shape as clean (`docs/plans/android-app-optimization-plan-2026-09-05.md`, results log). Any change to that shape must be launched on a device before it ships; a green build proves nothing there. That same plugin also compiles React Native **from source** on Android (`includeBuild('../node_modules/react-native')`) so the patched `StatusBarModule`/`WindowUtil` in `ugc-mobile/patches/react-native+*.patch` take effect; ReactAndroid's native build pins a CMake version (3.30.5 for 0.83) that the EAS builder image lacks, so `ugc-mobile/scripts/install-android-cmake.mjs` runs as the `eas-build-post-install` hook to install it — and a source build for four ABIs overran the EAS free plan's 45-minute build limit (build 68 was cancelled in the last native step), so the EAS `production` profile pins `ORG_GRADLE_PROJECT_reactNativeArchitectures=armeabi-v7a,arm64-v8a`; local and dev builds keep all four ABIs from `gradle.properties`.
