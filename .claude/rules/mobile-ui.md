# Mobile UI rules: HIG, native APIs first, the theme hook

Moved unchanged from `AGENTS.md` on 2026-10-18 so it loads only where it applies; the core file keeps a summary and points here.

- **Mobile UI is held to Apple's HIG**: check visual and layout changes in `ugc-mobile/` against the Human Interface Guidelines before shipping them. The numeric floors are enforced by `ugc-mobile/__tests__/hig-type-and-contrast.test.ts` — 11pt minimum type, 4.5:1 body contrast on every panel surface, 44pt hit regions (geometry in `ugc-mobile/lib/hit-target.ts`) — so a red guard is a real violation: fix the control, never the threshold. Adopting a further HIG rule means extending those guard tests so every later screen inherits it, not fixing one instance. Reading the guidelines: the HIG pages (developer.apple.com/design/human-interface-guidelines) are client-rendered, so a plain fetch returns only the page title — but the full text of any page is plain JSON at `developer.apple.com/tutorials/data/design/human-interface-guidelines/<page>.json` (curl works), and a rendering browser reads the pages normally. developer.apple.com/design/tips/ is a static one-page summary of the key numbers. Note the full HIG carries nuance the summary lacks — e.g. 44×44pt is the *default* control size on iOS; 28×28pt is the absolute floor.
- **Look for a native API before building a behaviour.** Before adding or changing anything a person sees or touches — a transition, a gesture, a sheet, a menu, a picker, playback, haptics, a system integration — first check whether the platform already provides it, and prefer that over anything hand-built in JS: it runs where the frames are made, it feels like the rest of the OS, and it costs nothing per frame on the JS thread. The reel's iOS open and close spent days on a JS-driven flight (`ugc-mobile/components/media-zoom.tsx`) that UIKit's own zoom transition (`UIViewController.Transition.zoom`, iOS 18) already did better, with interactive dismissal for free — and Expo Router 55 had shipped a binding for it (`Link.AppleZoom`; ours is `ugc-mobile/lib/apple-zoom.ts`). Where to look, in this order: Apple's UIKit/SwiftUI docs — the HTML is client-rendered, so read the JSON at `developer.apple.com/tutorials/data/documentation/<framework>/<symbol>.json` — and the Android platform and Material docs; then the installed Expo SDK modules, `expo-router` and `react-native-screens` for a binding (`node_modules/<package>/ios`, `/android`, its `CHANGELOG.md`, and the `expo/skills` references); then the wider React Native ecosystem; and on the web, the browser first (View Transitions, `<dialog>`, `popover`, scroll snap, `<details>`). Say in the plan doc or PR what was checked and why the choice was made. Three limits go with the rule: a platform API covers one platform and an OS floor, so the other platform and older OS versions need a stated fallback; it needs a native build unless the binary in users' hands already contains it (see Mobile ships separately — check before promising an OTA); and unit tests cannot see it, so it is verified on a device or simulator, never declared done from a green test.
- **Mobile colours come from the theme hook**: read scheme-dependent tokens (`colors`, `semantic`, `state`, `shadow`, `dim`, `tabBar`) through `useAppTheme()` (`ugc-mobile/lib/theme-context.tsx`) — `appTheme` carries only static tokens, because a colour read from a module constant is memoised by React Compiler and never redraws on a scheme switch. A coral *fill* is `primaryFill` (bright in both schemes, ink on it); `primary` is coral as text and thin marks, and goes deep on light. Colours drawn over pictures come from `mediaColors`; surfaces that stay dark (reel, zoom flight, lightbox, onboarding) sit in `<ThemeScope scheme="dark">`. `__tests__/theme-color-literals.test.ts` fails any raw colour literal outside its `EXEMPT` list. The scheme is resolved in `ugc-mobile/lib/appearance.ts` (the phone, or the Settings → Appearance override); light mode reaches phones only in a binary built from `userInterfaceStyle: "automatic"` — its native half is a store build, never an OTA.
