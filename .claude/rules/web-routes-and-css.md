# Web styling and routing

Moved unchanged from `AGENTS.md` on 2026-10-18 so it loads only where it applies; the core file keeps a summary and points here.

- **CSS split**: `globals.css` is the stylesheet for every route a signed-out visitor can land on (marketing, blog, models, post/creator/referral landings, templates, search, login/auth, and the policy pages: terms, privacy, child safety, cancellation, account deletion); signed-in surfaces add `non-public-utilities.css` via their route layouts, those that also draw for a signed-out visitor included (the image, video and motion creators a visitor uses up to Generate; Search left the list on 2026-11-24, its page and component closure adding about 5 KB, 0.4 KB brotli, to `globals.css` against the 40 KB br the supplement cost a signed-out `/search` view). Alerts, the shell's tab on every page, is the exception: its sign-in card draws on `globals.css`, and its signed-in half (`notifications/SignedInAlerts.tsx`, which `globals.css` skips with `@source not`) links the supplement itself and is loaded with `import()` once the session check finds a reader, so a signed-out click on the tab no longer fetches the signed-in sheet and keeps it for the visit. Each use of the half sits in `notifications/SignedInAlertsBoundary.tsx`: a load that fails (a deploy rotated the chunk names while the tab was open; offline) draws the page's own error card, `AlertsErrorCard.tsx`, a file `globals.css` scans since the half's sheet never arrived either, with a Retry that reloads, so the failure stays inside the half and the reload fetches the current chunk names. Without it a rejected `import()` would reach the root `src/app/error.tsx` (until 2026-11-27 there was none, and it reached Next's generic client-exception page), which would replace the whole page, and whose Retry re-fetches the segment without a reload, so the lazy load would keep the failed chunk. The boundary hands the caught error on to `window.reportError`, so Sentry still hears it. CSS is inlined via `experimental.inlineCss`, which duplicates the sheet per response, so a public route must never import the supplement. The supplement loads later and shares the utilities layer, so a utility it emits outranks every rule of `globals.css` of the same weight, whatever order Tailwind gave the two: its `.hidden` hid the top bar's "New creation" (`md:inline-flex` lived only in `globals.css`), and its `h-8` beat the reel's `lg:h-px` on the profile. And it outlives its routes: React keeps a stylesheet it has inserted, so every page a client navigation opens afterwards, public ones included, is drawn with both sheets (on 2026-10-19 the blog's title kept 36px for 48px and Pricing its phone padding on a laptop until a reload, live too; 39 such pairs in 15 public files). So the supplement scans the whole app folder but `api` and the whole components folder (`@source "./"`, `@source not "./api"`, `@source "../components"`, plus the lib registries any route imports): it holds every utility a page can carry, `globals.css`'s included, and its own order, which is Tailwind's, decides on every page. That costs every full load of a route that links it about 20 KB more minified CSS per copy, inlined twice (about 43 KB decoded, 1.6 KB brotli per copy), and a signed-out first load of a public page nothing. `route-style-readiness.test.ts` lists every route folder as public or signed-in (one in neither fails), pins which directories link which sheet (`globals.css` scans exactly the public route folders, and no file a public route draws imports the supplement), holds `globals.css` to the public routes' import closure file for file (a file of a signed-in folder that a public page draws is named one by one: the profile editor a creator opens on their own page, which on a full load lost its focus rings, crop guides and slider colour while only the supplement held them) and the supplement to those three lines and the registries, holds a lazy boundary such as Alerts' signed-in half to `import()` alone and out of `globals.css`, and refuses a bracketed folder in any `@source` line (the glob takes `[id]` for a set of letters and the line matches nothing). `route-style-two-sheet-order.test.ts` compiles both sheets and fails unless every utility rule of `globals.css` is in the supplement, compiled the same way and in the same order (a breakpoint or theme token changed in one `@theme` block only would move its media query), and caps the supplement's size; `tests/e2e/public-page-after-signed-in-route.spec.ts` draws Pricing and the blog after a client navigation from Credit history, and `tests/e2e/alerts-signed-out-sheet.spec.ts` keeps the supplement out of a signed-out visit to Alerts. The `.app-shell-*` and `.home-*` named classes in `globals.css` are the earlier fix for the same fault and stay: the shell does not depend on two sheets' order.
- **Error pages** (2026-11-27): `src/app/error.tsx` catches a failure on any route with no error file of its own (Home, Pricing, the creators, the profile) and draws "Something went wrong" inside the app shell, on `globals.css` alone, with Retry and Go to Home; `src/app/showcase/[id]/error.tsx` draws "Could not load this post" on the post page, with Retry and Back to Explore, in place of the showcase folder's "Could not load Explore". Both call `retry`, which re-fetches the segment and then resets (`reset` alone re-renders the same errored payload), and both use plain markup, since an error file rides in every page's first load (`post-page-first-load-imports.test.ts`). Client code reads an API answer through `readJsonResponse` (`src/lib/read-json-response.ts`), never a bare `await response.json()` before or inside its `!response.ok` branch: the platform answers a timed-out function with an HTML 502 or 504, whose parse error was shown to people. An action that spends credits or money asks `isUnconfirmedOutcome` and says the result is unknown rather than failed. `client-json-before-ok.test.ts` holds that rule. The shell draws the one `<main>`, so a page's own region is a `<div>` or a labelled `<section>` (`single-main-landmark.test.ts`), and the studio's preview, the media details viewer, the canvas's preview and the composer's lightbox keep Tab inside themselves with `keepTabInside` (`src/lib/focusable-elements.ts`).
- **Rewrites defeat route interception**: the signed-in `/` is served through a rewrite to `/home` in `src/proxy.ts` (nothing in `next.config.ts`; `/showcase` and `/marketplace` are ordinary routes, and `/feed` a page that redirects to `/`), and Next route interception (the post-overlay pattern) never fires on a rewritten path — plan overlay UX accordingly.
