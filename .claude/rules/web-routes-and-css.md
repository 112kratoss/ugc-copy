# Web styling and routing

Moved unchanged from `AGENTS.md` on 2026-10-18 so it loads only where it applies; the core file keeps a summary and points here.

- **CSS split**: `globals.css` is the stylesheet for every route a signed-out visitor can land on (marketing, blog, models, post/creator/referral landings, templates, login/auth, and the policy pages: terms, privacy, child safety, cancellation, account deletion); signed-in surfaces add `non-public-utilities.css` via their route layouts, those that also draw for a signed-out visitor included (Search's results). Alerts, the shell's tab on every page, is the exception: its sign-in card draws on `globals.css`, and its signed-in half (`notifications/SignedInAlerts.tsx`, which `globals.css` skips with `@source not`) links the supplement itself and is loaded with `import()` once the session check finds a reader, so a signed-out click on the tab no longer fetches the signed-in sheet and keeps it for the visit. Each use of the half sits in `notifications/SignedInAlertsBoundary.tsx`: a load that fails (a deploy rotated the chunk names while the tab was open; offline) draws the page's own error card, `AlertsErrorCard.tsx`, a file `globals.css` scans since the half's sheet never arrived either, with a Retry that reloads — `src/app` has no `error.tsx`, so a rejected `import()` otherwise reached Next's generic client-exception page. CSS is inlined via `experimental.inlineCss`, which duplicates the sheet per response, so a public route must never import the supplement. The supplement loads later and shares the utilities layer, so a utility it emits outranks every rule of `globals.css` of the same weight, whatever order Tailwind gave the two: its `.hidden` hid the top bar's "New creation" (`md:inline-flex` lived only in `globals.css`), and its `h-8` beat the reel's `lg:h-px` on the profile. And it outlives its routes: React keeps a stylesheet it has inserted, so every page a client navigation opens afterwards, public ones included, is drawn with both sheets (on 2026-10-19 the blog's title kept 36px for 48px and Pricing its phone padding on a laptop until a reload, live too; 39 such pairs in 15 public files). So the supplement scans the whole app folder but `api` and the whole components folder (`@source "./"`, `@source not "./api"`, `@source "../components"`, plus the lib registries any route imports): it holds every utility a page can carry, `globals.css`'s included, and its own order, which is Tailwind's, decides on every page. That costs every full load of a route that links it about 20 KB more minified CSS per copy, inlined twice (about 43 KB decoded, 1.6 KB brotli per copy), and a signed-out first load of a public page nothing. `route-style-readiness.test.ts` lists every route folder as public or signed-in (one in neither fails), pins which directories link which sheet (`globals.css` scans exactly the public route folders, and no file a public route draws imports the supplement), holds `globals.css` to the public routes' import closure file for file (a file of a signed-in folder that a public page draws is named one by one: the profile editor a creator opens on their own page, which on a full load lost its focus rings, crop guides and slider colour while only the supplement held them) and the supplement to those three lines and the registries, holds a lazy boundary such as Alerts' signed-in half to `import()` alone and out of `globals.css`, and refuses a bracketed folder in any `@source` line (the glob takes `[id]` for a set of letters and the line matches nothing). `route-style-two-sheet-order.test.ts` compiles both sheets and fails unless every utility rule of `globals.css` is in the supplement, compiled the same way and in the same order (a breakpoint or theme token changed in one `@theme` block only would move its media query), and caps the supplement's size; `tests/e2e/public-page-after-signed-in-route.spec.ts` draws Pricing and the blog after a client navigation from Credit history, and `tests/e2e/alerts-signed-out-sheet.spec.ts` keeps the supplement out of a signed-out visit to Alerts. The `.app-shell-*` and `.home-*` named classes in `globals.css` are the earlier fix for the same fault and stay: the shell does not depend on two sheets' order.
- **Rewrites defeat route interception**: the signed-in `/` is served through a rewrite to `/home` in `src/proxy.ts` (nothing in `next.config.ts`; `/showcase` and `/marketplace` are ordinary routes, and `/feed` a page that redirects to `/`), and Next route interception (the post-overlay pattern) never fires on a rewritten path — plan overlay UX accordingly.
